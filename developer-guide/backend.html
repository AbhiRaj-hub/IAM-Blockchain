BEL TrustChain — Backend Architecture & Code Deep-Dive

A comprehensive guide explaining the Node.js/Express application layer, dual-engine storage resilience, cryptographic hashing, and microservice inter-process communication.

1. High-Level Backend Overview & Request Lifecycle

The BEL TrustChain backend is a high-performance, asynchronous REST API service built on Node.js and Express.js. It acts as the central coordinator between the frontend web client, the storage database, and the Python Proof-of-Work blockchain service.

The Full Request-Response Journey

[Browser Client] 
       │  (1) HTTP Request + Bearer JWT
       ▼
[server.js] ──▶ CORS & JSON Body Parsing
       │
       ▼
[Route Layer] (e.g. accessRoutes.js)
       │
       ▼
[Middleware Layer] ──▶ authMiddleware (Verifies JWT) ──▶ roleMiddleware (Checks RBAC)
       │
       ▼
[Controller Layer] (e.g. accessController.js) ──▶ Business Logic & Input Sanitization
       │
       ├───▶ (2) [blockchainService.js] ──▶ HTTP POST to Python Blockchain (Port 5001)
       │                                     • Mines Proof-of-Work Block
       │                                     • Returns block_index & block_hash
       │
       └───▶ (3) [Database / Mirror Layer] (Mongoose Proxy / localStore.js)
                                             • Indexes record for fast search & filtering
       │
       ▼
[Client Response] ◀── Returns JSON payload + Blockchain Anchor Metadata

2. Server Entry Point & Middleware Mounting (`server.js`)

backend/server.js

server.js initializes the Express application, configures security headers, mounts static asset directories, registers modular API routes, and establishes a centralized error-handling boundary.

Core Code Implementation:

const express = require('express');
const cors = require('cors');
const dotenv = require('dotenv');
const path = require('path');
const connectDB = require('./config/db');

dotenv.config();
connectDB(); // Attempt MongoDB Atlas connection with automatic offline fallback

const app = express();

// 1. Core Global Middlewares
app.use(cors());
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// 2. Static File Serving
app.use(express.static(path.join(__dirname, '..', 'frontend')));
app.use('/guide', express.static(path.join(__dirname, '..', 'developer-guide')));

// 3. API Route Mounting
app.use('/api/auth', require('./routes/authRoutes'));
app.use('/api/identity', require('./routes/identityRoutes'));
app.use('/api/access', require('./routes/accessRoutes'));
app.use('/api/assets', require('./routes/assetRoutes'));
app.use('/api/audit', require('./routes/auditRoutes'));

// 4. Centralized Error Handler
app.use((err, req, res, next) => {
  console.error('[Server Error Handler]:', err.stack);
  res.status(err.status || 500).json({
    success: false,
    message: err.message || 'Internal Server Error',
  });
});

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`🛡️ BEL TrustChain running on http://localhost:${PORT}`));
What this code does:
  • Loads environment variables from .env.
  • Connects to the database asynchronously without blocking web requests.
  • Mounts the frontend single-page application at / and this developer guide at /guide.
  • Ensures that unexpected runtime exceptions are caught by the 4-argument error handler middleware rather than crashing the Node process.

3. The Resilient Dual-Engine Database (`localStore.js` & Proxies)

backend/models/localStore.js & backend/models/User.js

One of the core engineering achievements of this project is the **Zero-Hang Dual-Engine Architecture**. If MongoDB Atlas is available, Mongoose executes queries against the cloud database. If the internet or MongoDB is unreachable, the system automatically routes queries to a local in-memory/JSON store (backend/data/db_store.json) without changing a single line of controller code!

3.1 The Transparent Model Proxy Pattern

// User.js
const mongoose = require('mongoose');
const { createOfflineModel } = require('./localStore');
const { getIsConnected } = require('../config/db');

const userSchema = new mongoose.Schema({ ... });
const MongooseUser = mongoose.models.User || mongoose.model('User', userSchema);
const OfflineUser = createOfflineModel('users', { matchPassword: true });

const UserProxy = new Proxy(MongooseUser, {
  get(target, prop) {
    if (getIsConnected()) {
      return target[prop]; // Route to MongoDB Atlas
    }
    if (typeof OfflineUser[prop] === 'function') {
      return OfflineUser[prop].bind(OfflineUser); // Route to Local JSON Engine
    }
    return target[prop];
  },
});

module.exports = UserProxy;

3.2 The Thenable QueryChain Engine

Mongoose queries allow chained operators such as await User.find().sort({ createdAt: -1 }).limit(10). localStore.js implements a custom QueryChain class that supports synchronous chaining and implements the JavaScript Thenable protocol (then()) so it can be awaited identically to Mongoose: 

class QueryChain {
  constructor(items, defaultMethods) {
    this._items = (items || []).map((i) => wrapDocument(i, defaultMethods));
  }

  sort(sortObj) {
    this._items.sort((a, b) => new Date(b.createdAt || 0) - new Date(a.createdAt || 0));
    return this; // Returns instance for chaining
  }

  limit(n) {
    if (typeof n === 'number') this._items = this._items.slice(0, n);
    return this;
  }

  select(fields) {
    return this;
  }

  // Resolves the promise when 'await' is executed
  then(resolve, reject) {
    return Promise.resolve(this._items).then(resolve, reject);
  }
}

4. Authentication & JWT Security Controller (`authController.js`)

backend/controllers/authController.js

Manages user onboarding, credential verification, and stateless JSON Web Token generation.

4.1 Multi-Strategy Password Matching

To ensure 100% login reliability during presentations while preserving high cryptographic security, authController.js executes multi-tier credential matching: 

const login = async (req, res) => {
  const { email, password } = req.body;
  const cleanEmail = String(email).trim().toLowerCase();
  const cleanPassword = String(password).trim();

  const user = await User.findOne({ email: cleanEmail });
  if (!user) {
    return res.status(401).json({ success: false, message: 'Invalid email or password credentials.' });
  }

  let isMatch = false;

  // 1. If wrapped Mongoose doc with custom matchPassword
  if (typeof user.matchPassword === 'function') {
    isMatch = await user.matchPassword(cleanPassword);
  } 
  // 2. Direct Bcrypt comparison against stored hash
  else if (user.password && user.password.startsWith('$2')) {
    isMatch = await bcrypt.compare(cleanPassword, user.password);
  } 
  // 3. Direct plaintext match fallback
  else if (user.password) {
    isMatch = cleanPassword === user.password;
  }

  if (!isMatch) {
    return res.status(401).json({ success: false, message: 'Invalid email or password credentials.' });
  }

  // Generate signed JWT token
  const token = generateToken(user);
  return res.status(200).json({ success: true, message: 'Login successful', data: { token, user } });
};

4.2 JWT Token Signing

The JWT payload securely encapsulates user identity, role, and clearance tier: 

const generateToken = (user) => {
  return jwt.sign(
    {
      id: user._id,
      role: user.role,
      clearanceLevel: user.clearanceLevel,
      did: user.did,
    },
    process.env.JWT_SECRET || 'bel_secure_key_2026',
    { expiresIn: '7d' }
  );
};

5. Decentralized Identity (DID) Controller (`identityController.js`)

backend/controllers/identityController.js

Handles self-sovereign identity generation conforming to did:bel:<hash>, calling the Python blockchain to mine an IDENTITY_ISSUE transaction, and indexing metadata in the local registry.

Issuing a DID:

const issueIdentity = async (req, res) => {
  const { userId, subjectName, role, clearanceLevel, issuer } = req.body;

  // 1. Mine IDENTITY_ISSUE transaction on Python Blockchain
  const blockchainRes = await blockchainService.issueIdentity(
    subjectName,
    role,
    clearanceLevel,
    issuer || 'BEL-Authority'
  );

  const did = blockchainRes.did;
  const blockIndex = blockchainRes.block_index;

  // 2. Index identity in database mirror
  const identityRecord = await Identity.create({
    did,
    userId: userId || null,
    credentialId: blockchainRes.credential_id,
    subjectName,
    role,
    clearanceLevel: Number(clearanceLevel),
    issuer: issuer || 'BEL-Authority',
    status: 'ACTIVE',
    blockchainBlockIndex: blockIndex,
  });

  // 3. Link DID to user account
  if (userId) {
    await User.findByIdAndUpdate(userId, { did, role, clearanceLevel });
  }

  return res.status(201).json({ success: true, data: identityRecord });
};

6. Access Control & Clearance Policy Engine (`accessController.js`)

backend/controllers/accessController.js

Implements the mathematical clearance evaluation policy: $$\text{Decision} = (\text{Clearance}_{\text{subject}} \ge \text{Clearance}_{\text{resource}}) \lor \text{HasActiveGrant}_{\text{on\_chain}}$$

Clearance Request Check:

const requestAccess = async (req, res) => {
  const { resource, requiredClearance } = req.body;
  const user = req.user;
  const did = user.did || `did:bel:${user._id}`;
  const userClearance = user.clearanceLevel || 1;
  const reqClearance = Number(requiredClearance);

  // 1. Evaluate policy and mine immutable ACCESS_ATTEMPT block on Blockchain
  const blockchainRes = await blockchainService.checkAccess(
    did,
    resource,
    userClearance,
    reqClearance
  );

  const decision = blockchainRes.decision; // 'ALLOWED' or 'DENIED'
  const blockIndex = blockchainRes.block_index;

  // 2. Save forensic audit log
  const logRecord = await AccessLog.create({
    did,
    resource,
    decision,
    reason: blockchainRes.reason,
    blockchainBlockIndex: blockIndex,
    timestamp: new Date(),
  });

  const isAllowed = decision === 'ALLOWED';
  return res.status(isAllowed ? 200 : 403).json({
    success: isAllowed,
    decision,
    message: isAllowed ? 'Access GRANTED' : 'Access DENIED',
    blockchainBlockIndex: blockIndex,
  });
};

7. Digital Asset Tokenization & Live Tamper Forensics (`assetController.js`)

backend/controllers/assetController.js & backend/services/assetService.js

Handles file uploads via multer, calculates the 256-bit SHA-256 digest, anchors the hash to the owner's DID on the blockchain, and provides live 1-byte disk tamper simulation.

7.1 SHA-256 File Digest Calculation:

const crypto = require('crypto');
const fs = require('fs');

function calculateFileHash(filePath) {
  const fileBuffer = fs.readFileSync(filePath);
  return crypto.createHash('sha256').update(fileBuffer).digest('hex');
}

7.2 Live Tamper Simulation (`tamperAssetDemo`):

const tamperAssetDemo = async (req, res) => {
  const asset = await findAssetByIdOrKey(req.params.id);

7.3 Cryptographic Integrity Verification (`verifyAsset`):

const verifyAsset = async (req, res) => {
  const asset = await findAssetByIdOrKey(req.params.id);
  const filePath = resolveAssetDiskPath(asset);

  // Recalculate hash of physical file on disk
  const currentHash = calculateFileHash(filePath);
  const expectedHash = asset.sha256;
  const isIntact = currentHash === expectedHash;

  return res.status(200).json({
    success: true,
    data: {
      expectedHash,
      currentHash,
      integrityIntact: isIntact,
      status: isIntact ? 'VERIFIED_AUTHENTIC' : 'TAMPERED_WARNING',
    },
  });
};

8. Middlewares: JWT Verification & RBAC Guards

backend/middleware/authMiddleware.js & roleMiddleware.js

8.1 `authMiddleware.js` (Bearer Token Verification):

const jwt = require('jsonwebtoken');

const protect = (req, res, next) => {
  let token;
  if (req.headers.authorization && req.headers.authorization.startsWith('Bearer')) {
    token = req.headers.authorization.split(' ')[1];
  }

  if (!token) {
    return res.status(401).json({ success: false, message: 'Not authorized: No token provided.' });
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET || 'bel_secure_key_2026');
    req.user = decoded;
    next();
  } catch (error) {
    return res.status(401).json({ success: false, message: 'Not authorized: Token invalid or expired.' });
  }
};

8.2 `roleMiddleware.js` (Role-Based Guards):

const authorizeRoles = (...allowedRoles) => {
  return (req, res, next) => {
    if (!req.user || !allowedRoles.includes(req.user.role)) {
      return res.status(403).json({
        success: false,
        message: `Forbidden: Role '${req.user ? req.user.role : 'UNKNOWN'}' is not authorized.`,
      });
    }
    next();
  };
};

9. Blockchain Inter-Service Communication (`blockchainService.js`)

backend/services/blockchainService.js

Encapsulates all Axios HTTP calls from Node.js (port 5000) to the Python Flask blockchain microservice (port 5001) with fallback handling and timeouts. 

const axios = require('axios');
const BLOCKCHAIN_URL = process.env.BLOCKCHAIN_API_URL || 'http://localhost:5001';

const issueIdentity = async (subjectName, role, clearanceLevel, issuer) => {
  const res = await axios.post(`${BLOCKCHAIN_URL}/identity/issue`, {
    subject_name: subjectName,
    role,
    clearance_level: Number(clearanceLevel),
    issuer,
  }, { timeout: 4000 });
  return res.data;
};

const checkAccess = async (did, resource, userClearance, requiredClearance) => {
  const res = await axios.post(`${BLOCKCHAIN_URL}/access/check`, {
    did,
    resource,
    user_clearance: Number(userClearance),
    required_clearance: Number(requiredClearance),
  }, { timeout: 4000 });
  return res.data;
};

const validateChain = async () => {
  const res = await axios.get(`${BLOCKCHAIN_URL}/chain/validate`, { timeout: 3000 });
  return res.data;
};
