11. Digital Asset Tokenization & SHA-256 Integrity

Asset Tokenization Model

In the ShieldX platform, digital assets (schematics, binaries, confidential documents) are tokenized on the blockchain:

  • Uniqueness: Every digital asset produces a distinct cryptographic SHA-256 fingerprint.
  • DID Allocation: Each token is directly bound to a user's Decentralized Identifier (e.g. did:sx:admin001).
  • Controlled Minting: Only authorized Administrators and Managers can mint and allocate asset tokens.

The Anchoring Workflow

Document Uploaded by Authorized Role
   ↓
Node.js computes crypto.createHash('sha256')
   ↓
Physical file stored in off-chain directory (uploads/)
   ↓
SHA-256 hash + owner DID sent to Python Blockchain API
   ↓
ASSET_ANCHOR transaction mined into permanent Block
   ↓
Fast searchable metadata mirror indexed in MongoDB / Local Store

How Verification & Tamper Detection Works

When an auditor clicks Verify Integrity:

  1. Node.js re-hashes the current physical file on disk.
  2. It compares the current hash against the blockchain-anchored expected hash.
  3. If currentHash === expectedHash: 100% Authentic.
  4. If currentHash !== expectedHash: TAMPERING DETECTED.
